## Текущая корректировка верхней метки · 22 ноября 2026

По повторному скриншоту из «ВторогоКрыла» **иконка и подпись «АДВЕНТ · 2026» должны находиться вместе в одной тёмной полупрозрачной плашке**. Нет отдельного фрейма, фона, бордера или второй плашки у иконки. Пример рабочей CSS-формулы: `rgba(0,0,0,.32)`, скругление 11 px, одна строка, календарная иконка с сеткой дат. Прямо под ней — «Открой свой календарь». **«40 дней до 2027» оставлено без изменений**, как просил автор.

Декоративную 3D-ёлку **пока убрали из входного баннера**. В будущем можно добавить праздничный мотив как часть фона, не как отдельную активную картинку. Сам календарь на отдельной полноэкранной странице; шторки только для деталей дней.

Рабочий HTML-прототип v5 и снимок сохранены в файлах разговора (скриншот хоста не публикуем в публичный репозиторий). Текущий Flutter-кандидат обновлён: одна тёмная плашка для иконки и текста, без фронтальной ёлки; нативная сборка ещё не выполнялась.

## Источник решения

По скриншоту стартового экрана приложения «ВтороеКрыло» баннер располагается **после трёх верхних карточек**, под двумя квадратными, **до заголовка «ВтороеКрыло» и основных кнопок**. Скриншот самого хост-экрана не публикуется в публичном репозитории. Исходников хост-приложения на доступном GitHub нет; это пока самостоятельный макет.

**Прямая просьба автора:** оставить «АДВЕНТ · 2026», «Открой свой декабрь» и число дней до Нового года; убрать «Открыто 0 из 31», прогресс и текст «Перейти в календарь»; желательно уместить заголовок в одну строку; заменить декоративный векторный папоротник **точной ёлкой из шапки**. Вместо modal/bottom sheet открывать **полноценную страницу календаря**, а уже события и советы внутри неё — в своих bottom sheet.

## Иерархия баннера

1. Слева сверху: маленькая календарная иконка и надстрочник **«АДВЕНТ · 2026»**.
2. Слева: **«Открой свой декабрь»**, по возможности одна строка, Yeseva One; на маленькой ширине допустим аккуратный перенос вместо переполнения.
3. Справа: **«40 дней до 2027»** (число — динамическое, пример соответствует 22 ноября 2026); после Нового года — спокойный праздничный вариант.
4. Позади счётчика справа: **исходное WebP-изображение стеклянной ёлки с синими шарами из hero**, частично кадрированное. **Никаких новых SVG-веток, папоротников или альтернативной ёлки**.
5. Больше ничего: без прогресса, лайков, «Открыто 0 из 31» и текстового дублирования CTA. **Вся карточка — одна кнопка**.

Высота текущего HTML-кандидата — около **125 px** при ширине 360 px, 121 px при очень узком экране; один зелёный фон и одна тонкая граница, без внешнего выступающего ободка. Тёплое золото на счётчике, очень тихий снег и блеск. Финальные размеры определяются после Flutter-ревью.

## Сценарий навигации

```text
Главная «ВтороеКрыло»
  └─ тап по баннеру «Открой свой декабрь»
       └─ НОВАЯ полноэкранная страница «Декабрь чудес»
            ├─ системная «Назад» → на главную
            ├─ тап по мероприятию → bottom sheet события
            └─ тап по доступному совету → bottom sheet совета
```

**Запрещённый паттерн:** открывать весь календарь как нижнюю шторку или модальный overlay. Шторки — только для деталей внутри полноэкранного календаря.

В самостоятельном HTML-демо экран календаря показан как full-screen route с собственным Back и встроенной существующей страницей GitHub Pages для демонстрации. Это **не нативная реализация**: в Flutter хост должен применить `Navigator.push` / его собственный router, а календарь перенести нативно, без iframe/WebView.

## Контракт Flutter

```dart
AdventEntryCard(
  daysUntilNewYear: daysFromCampaignClock,
  onOpen: () => Navigator.of(context).push(
    MaterialPageRoute(builder: (_) => const AdventCalendarScreen()),
  ),
)
```

- Вход: `daysUntilNewYear`, `onOpen`, опциональный путь к tree asset. **Никакого `openedDays` в карточке входа.**
- Даты рассчитывает **хост** в часовой зоне кампании; при наступлении нового календарного дня он передаёт обновлённое значение.
- Исходник дерева в репозитории: `flutter/assets/advent/hero_tree.webp`. При переносе скопировать как `assets/advent/hero_tree.webp` в приложении и зарегистрировать в `pubspec.yaml`; Flutter-кандидат уже использует этот asset.
- Не использовать в production ни параметры `?preview` / `?frost`, ни screenshot-backed HTML-прототип.
- Нет хост-репозитория, поэтому пока нет действующего маршрута, интеграции или APK.
