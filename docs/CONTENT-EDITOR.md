# Редактирование календаря

Менять production-контент нужно только в **[content/calendar_2026.json](../content/calendar_2026.json)**.
Node.js 22 достаточен для генерации; Flutter SDK для редакторских команд не нужен.
Формат `advent-content`, schemaVersion 1; [JSON Schema](../content/calendar.schema.json)
помогает редактору, генератор дополнительно проверяет даты, идентификаторы и файлы арта.

## Мероприятие и совет

Найдите запись по `date`, например `2026-12-19`. Не меняйте `id`, `date`, campaignId,
year/month и каталог assets ради обычной правки. Идентификаторы привязаны к данным
пользователя; новая схема/кампания требует отдельного согласования и миграции.

- Мероприятие: правьте `event.title`, `shortTitle`, `desc`, `time`, `duration`, `place`.
  Не теряйте `sourceCopy`, `cardLines`, `cta`, `verification`, если они есть.
- Совет: `advice.title`, `text`, `action` есть **на всех 31 датах**, включая мероприятия.
- Добавление: вместо `event: null` вставьте объект по образцу существующего event,
  заполните обязательные поля и его `columns`, `art`, `theme`, `verification`.
  Не копируйте чужие время/место как предполагаемые данные.
- Удаление: установите **`event: null`**. Совет и его оформление останутся в записи
  и автоматически вернутся в HTML/Flutter. Не удаляйте всю дату или её advice.

`time` — исходная надпись (`HH:mm`, «Не указано», «В течение дня» и т. п.).
`duration` — подтверждённое исходником число минут либо `null`. `place` — исходная
строка; если данных нет, редактор явно указывает это, генератор не подставляет
догадки. Flutter-поля startTime и locations вычисляются только из этих строк:
строгий HH:mm либо null; разделение исходного place по «; ». Время/длительность
не придумываются. `verification` сохраняет статус источника, а не подтверждает
его автоматически; текущие события требуют дополнительного подтверждения.

## Оформление и сюрпризы

`advice.art`, `theme` (`""` или `"alt"`), `columns` (1/2) — сохранённое оформление
совета, используемое при отсутствии мероприятия. `event.art`, `theme`, `columns`
и необязательные `cardLines` относятся только к мероприятию.

Выбирайте существующий ключ из `assets`: gift, tree, orb, letter, snow, cocoa,
heart, bell, star, cube, moon, spark, champagne, citrus, moneybag, hero_tree,
snowMaiden. Темы мероприятий: ruby, green, moss, purple, sand, ice, night.
Каталог указывает на прежние Flutter-файлы, а HTML сохраняет прежние встроенные
байты изображений. Добавление нового изображения — отдельная согласованная
правка ресурсов, включая standalone HTML; не заменяйте картинки при редактуре.

`revealOnDate` согласован только для 4/9/11/15. Флаг активен **только при наличии
event**. После удаления события отображается обычный совет; флаг остаётся в
master как договорённость для возможного восстановления события. Сохранённый
claim не сбрасывается. Новые даты-сюрпризы требуют изменения согласованного
контракта, не случайного включения флага.

## Команды из корня репозитория

```text
node tools/generate-content.cjs
node tools/generate-content.cjs --check
node tools/verify-content.cjs
node --test tools/content.test.cjs
node tools/export-content.cjs
```

Генерация обновляет только отмеченные GENERATED-блоки index.html и совместимый
flutter/assets/advent/calendar_2026.json. Их не нужно редактировать вручную.
`--check` ничего не пишет и падает при рассинхронизации; это обязательный CI gate.
Пустые/дублированные даты, пропущенный advice, неизвестный art/поле или некорректное
время блокируют генерацию. Число мероприятий не ограничено 14: 31/14/17 — текущая
утверждённая редакция, отдельно защищённая snapshot/кампанийными тестами.

CSV по умолчанию: **build/content/calendar_2026.csv**. Иной путь:

```text
node tools/export-content.cjs --out build/content/editor-copy.csv
```

UTF-8 с BOM для русских текстов, RFC-style кавычки и многострочные поля. CSV
содержит и совет, и event каждой даты, время/место, статус, оформление и строки.
Это экспорт, не второй источник и не вход для автоматического обратного импорта.

## Предпросмотр и готовность

Откройте самостоятельный index.html в браузере; **`?preview=31`** показывает
будущие даты через существующий QA-preview. `?preview=3` позволяет проверить
закрытые состояния. В production Flutter не добавляется виртуальная дата/QA UI.
Контент из feature-ветки не появится на публичном Pages до одобренного merge.

Проверьте diff: актуальные тексты должны измениться в master и обоих выходах,
стили/изображения/неотмеченные области HTML — остаться прежними. Выполните команды
выше и CI; CSV доступен также как artifact advent-editor-csv. Browser acceptance
advent-content-preview-tests и lossless visual artifacts показывают результат.

Текущая утверждённая редакция защищена fingerprint-fixture
tools/fixtures/calendar-2026-approved.json и тестами текущей кампании 31/14/17.
Они **не часть схемы/загрузчика**: намеренная новая редакция может иметь другое
число событий, что отдельно проверяется на 15/13/0. При согласованной редактуре
контрольный snapshot и ожидания кампанийных/визуальных fixture обновляются в PR
осознанно по фактическому новому контенту; не обходите их ради случайной регрессии.
Это не требует ручного редактирования второго production-представления.

Не сбрасывайте хранилище при добавлении/удалении event. Raw opened/saved/revealed
остаются с прежними ключами; сохранённый совет скрыт на активной event-дате и
возвращается после удаления event. Прогресс А начисляет просмотр по полной
московской дате, независимо от смены типа карточки.

После успешного CI — review автора и отдельное разрешение merge. Подпись demo,
versionCode, backend и интеграция хоста редакторскими командами не затрагиваются.
