# Прогресс «Твоя история декабря» · 24 ноября 2026

Вариант А: засчитывается уникальный просмотренный день, полная дата которого уже
наступила в Europe/Moscow. Ранний просмотр обычного мероприятия сохраняется сразу,
но прогресс увеличивается только в его дату. Повторное открытие не требуется.

Пример opened = 1, 2, 8 декабря: 1 декабря → 1/31; 2 декабря → 2/31;
8 декабря → 3/31. Непросмотренная дата не добавляется сама. После отсутствия
результат вычисляется по той же формуле при следующем входе.

## API и хранение

- AdventCalendar.isAvailable отвечает только за доступность: обычные мероприятия
  заранее, советы и 4/9/11/15 — с даты. Его поведение не менялось.
- AdventCalendar.open возвращает полное множество известных фактов просмотра,
  включая будущие мероприятия; не теряет их при открытии другой карточки.
- AdventCalendar.eligibleProgress(opened, campaignDate) — единственная доменная
  проекция: известные уникальные opened id с day.date <= campaignDate. Сравнение
  включает год, месяц, день; неизвестные id игнорируются, максимум 31.
- AdventProgress.open проверяет доступность и вызывает recordOpened, как прежде.
  AdventProgress.read перечитывает сырые просмотры и применяет общую проекцию
  к CampaignTime.today после чтения. Устройство не определяет пояс кампании.
- ProgressRepository.read возвращает raw opened, а не показанный счётчик.
  Нельзя сохранять отфильтрованный результат обратно вместо opened.
- LocalAdventRepository, ключи v1/user/campaign и формат bool не менялись.
  Нет удаления данных, миграции, дополнительного persisted counter или backend.

Существующий opened id является фактом просмотра по новым требованиям, в том числе
старый opened сюрприза без более нового revealed-флага. С даты он засчитывается,
но read не вызывает claimSurprise и не расходует одноразовое конфетти. Для нового
пользователя одна лишь полночь не создаёт opened и ничего не засчитывает. Хранилище
SurpriseRepository по-прежнему нужно для первого показа конфетти, а не для счётчика.
Избранное и прогресс независимы.

## Обновление UI

Пересчёт выполняется при входе, после просмотра, таймером московской полуночи и
при resume. В памяти UI остаётся одна производная проекция creditedDays. Её
ValueNotifier одновременно обновляет панель и уже открытую шторку истории;
отдельного независимого счётчика в шторке нет. После перезапуска источник прежний
LocalAdventRepository, пересчёт не требует посещения приложения в нужную дату.

Название, X/31, градиент и геометрия бара, Bento, типографика, анимации, арт,
доступность, избранное и конфетти сохранены. В шторке «Открыто» уточнено до
«Засчитано», а пояснение говорит о наступившей дате и сохранении раннего просмотра.
Фоновые службы, push и серверные задачи не нужны.

## Проверки

Unit/widget: ранние 1/2/8 и автоматическое начисление; сохранение будущих фактов
через pure domain API; непросмотренные даты; пропущенный совет и повторы; верхняя
граница 1/31 в первый день, 31/31 после кампании; полные даты/годы; московская
полночь при LA/Tokyo; прежние ключи и восстановление без записи/миграции; отдельный
первый сюрприз и избранное. Widget-сценарии проверяют просмотр будущего события,
resume после отсутствия, полночь с открытой историей и пересоздание экрана.

HTML и JSON-контент не редактируются: verifier проверяет 31/14/17 и исходный арт.
В парных снимках HTML остаётся старый принцип прогресса; различие счётчика и
пояснения намеренное, не визуальный дефект. Например, в fixture с семью ранними
обычными событиями на 15 декабря Flutter считает 6 (16-е ещё впереди), HTML — 7.
Android integration дополнительно проверяет 2/31 на 2 декабря при семи raw views.

После успешных CI и Android-сценария публикация APK/ссылки README выполняется
существующим Publish Android preview. PR #6 не сливается, index.html и Pages не меняются.
