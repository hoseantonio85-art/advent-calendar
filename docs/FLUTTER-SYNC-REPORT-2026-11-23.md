## Сюрпризы и хранение

До даты — Snow Maiden cover/center, дата слева сверху, небольшое стеклянное
«Сюрприз» слева снизу. Без реального названия, старого арта, вопроса, снежинки,
шарика, снега и инея поверх фото. Тап показывает исходное сообщение о дате раскрытия.
В 00:00 Europe/Moscow и при resume появляется обычное мероприятие без изменения
прогресса. Первое фактическое открытие отмечается отдельно от старых opened.
Конфетти: 18 частиц, 1450 ms, только область арта шторки; reduced motion отключает
движение, но первый просмотр всё равно отмечается.

Новый SurpriseRepository обязателен для полноценного custom host-хранилища:
readSurprises(campaignId) и атомарный claimSurprise(campaignId, dayId) → firstView.
ProgressRepository-адаптер реализует оба интерфейса. LocalAdventRepository уже готов:
отдельная группа bool-ключей revealed, тот же user/campaign scope, старые opened и
saved не очищаются. Atomic claim сериализован внутри isolate; многопроцессный или
серверный адаптер обязан обеспечить свою транзакцию. UI сначала проверяет доступность
через AdventProgress.open, затем claimSurprise и перечитывает прогресс. Без этого
нового интерфейса старый адаптер не засчитывает сюрпризы и не проигрывает конфетти.
При создании своего экрана хост должен повторить этот порядок. Это локальное
UX-скрытие статических данных, не серверная защита контента.
