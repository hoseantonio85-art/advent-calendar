# Локальное хранение и системные действия · Issue #4

LocalAdventRepository реализует ProgressRepository и SavedAdviceRepository поверх
SharedPreferencesAsync через заменяемый AdventBoolStorage. Для каждой даты отдельный
bool-ключ: параллельные открытия разных дат не перезаписывают общий список. Повторные
открытия идемпотентны. Сохранённые советы отделены от opened, допускаются только advice.
Неизвестные id/кампании отклоняются; read не возвращает чужие ключи.

Хост обязан передать стабильный несекретный userId и сбросить маршрут календаря при logout.
Префикс v1 + base64url userId + campaignId отделяет данные пользователей и кампаний.
Это не механизм авторизации и не шифрование. После переустановки/очистки данных прогресс
может исчезнуть; между устройствами синхронизации нет. Backend не нужен для этого пилота.
Если появится требование синхронизации, интерфейс заменяется адаптером хоста/сервера.

Demo использует локальный scope standalone-demo и восстанавливает состояние после
перезапуска. Это не учётная запись «ВторогоКрыла». Хост не должен использовать demo scope.

NativeAdventActions: share_plus для системного share с anchor для iPad;
add_2_calendar открывает редактор события Android/iOS, без прямой записи в календарь.
На web/desktop calendar возвращает unavailable. Cancellation share/confirmation
обрабатывается отдельно; исключения передаются UI, который показывает повторяемую ошибку.
completed для календаря означает запуск редактора, а не доказанное сохранение события.

Перед любым calendar export вызывается обязательный confirmCalendar. Demo показывает
исходное время/место и требует явного выбора. Без времени запрещено придумывать часы:
разрешён только явно выбранный all-day. Timed export строится в Europe/Moscow и передаёт
тот же instant устройству с любой зоной. All-day сохраняет civil date; конец 31 декабря —
1 января 2027. Неподтверждённые исходные поля не превращаются в подтверждённые этим действием.

ОС-права, фактический результат сохранения и поведение при отказе проверяются на устройствах.
CI проверяет адаптеры через заменяемые функции, анализ, web build и debug Android build.
Реальная интеграция с host router/account остаётся до доступа к «ВторомуКрылу».

## Шрифты

В assets/fonts добавлены немодифицированные Yeseva One и Roboto с SIL OFL 1.1.
Источник: google/fonts, ofl/yesevaone и ofl/roboto. Blob SHA:
YesevaOne-Regular.ttf: 8c22da37c23bd976e696575a5cb223b88909a2fe;
Roboto-Variable.ttf: 5522a368d9072fd88c299916e61fcff369949061.
Тексты лицензий сохранены рядом. Шрифты зарегистрированы в pubspec; используется
package-qualified family. Они доступны offline, хосту не нужно скачивать их при запуске.
Лицензии шрифтов не подтверждают права на фотографию входной карточки и иллюстрации.

## Визуальная проверка

CI отдельно снимает Flutter с настоящими шрифтами на 320/360/390/430 dp, событие и совет;
HTML снимается Chromium в той же дате 15.12.2026, 390×844, reduced motion.
Снимки помечены ADVENT_PNG только в QA-логах, не включены в пользовательское приложение.
Это позволяет сравнивать реальный рендер, а не объявлять визуальную точность по unit-тестам.
