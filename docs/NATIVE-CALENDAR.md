# Нативный календарь · Issue #2

Новый публичный AdventCalendarScreen: полноценный маршрут, SafeArea, трёхколоночная
Bento-сетка с row-flow и пропусками как в CSS, шторки с drag-to-dismiss и закреплённым
заголовком/закрытием. Все тексты и WebP из проверенного content bundle.

Экран принимает content/time/progress, optional actions/savedAdvice/onExit.
При отсутствии адаптера соответствующее действие отключено. Сохранённые советы
отделены от прогресса через SavedAdviceRepository. Нет backend, likes, тем и QA-дат.

Московская полночь и resume обновляют дату/прогресс. Закрытые советы не открываются.
Прогресс записывается перед sheet; повторный тап не создаёт вторую sheet. Ошибки
хранилища и действий показывают сообщение, cancellation не считается ошибкой.
Таймер/анимация освобождаются при уходе; reduced motion останавливает снег/золото.
Размеры по HTML: 104/111/124 dp, промежутки 5/6/8 dp, 3 колонки на 320–430 dp.
При увеличенном тексте высота карточек растёт, чтобы сохранить читаемость.

Demo в flutter/example показывает v9 → календарь → детали → назад, использует
настоящее московское время и хранит состояние только в памяти сессии. Системные
share/calendar отключены, пока хост не передал адаптер. Это не production-хранилище.

Запуск: cd flutter/example; flutter pub get; flutter create --platforms=web,android,ios
--project-name advent_demo .; flutter run. Сгенерированные платформенные файлы
не относятся к feature-package. CI анализирует пакет/demo, запускает тесты и web build.

Ограничения: Yeseva One/Roboto должен предоставить хост (права и font assets пока
не получены); используются font-family и fallback. Иней/орнамент/снег перенесены
нативной отрисовкой; точное визуальное совпадение с HTML требует screenshot/device QA.
Hero использует тот же WebP, но его дыхание ещё не перенесено. Android/iOS, screen reader,
производительность, системные адаптеры, durable storage и лицензии остаются открыты.
index.html и публикация GitHub Pages не изменены.
