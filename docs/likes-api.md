# Общие лайки — историческое API-предложение (v8, 21.11.2026)

> **АРХИВ · не входит в текущий MVP.** 21 ноября 2026 лайки и их API-адаптеры были удалены из единственной активной реализации Advent Calendar. Этот документ сохранён **только для истории исследованного варианта**, а не как задание на разработку. При переносе календаря на Flutter **не реализовывать лайки** без отдельного продуктового решения. Актуальный план: [ROADMAP.md](ROADMAP.md).

Это **предлагаемый контракт**, не описание подключённого сервера. Текущий HTML работает автономно, без доступа к бэкенду.

## Ожидаемое поведение

- Один лайк на событие от одного авторизованного пользователя; повторное нажатие снимает его.
- Общая сумма лайков = число уникальных пользователей, у которых `liked=true` для события.
- Пользователь идентифицируется **сервером** по существующей авторизации приложения. Нельзя принимать произвольный `user_id` в теле запроса и верить ему.
- Счётчик может обновляться при открытии карточки / после лайка. Real-time через WebSocket не обязателен на MVP.
- Ранее открытые события доступны и после окончания дня.
- Если запрос не удался, показывать ошибку и не подменять её локальным «общим числом».

## Встраивание через API-хост

До подключения основного скрипта календаря платформа задаёт конфигурацию:

```html
<script>
window.ADVENT_CONFIG = {
  apiBase: "/api",
  timeZone: "Europe/Moscow" // необязательно; только для определения текущего календарного дня
};
</script>
```

HTML использует эти endpoint'ы (предложение, необходимо согласовать с бэкендом):

| HTTP | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/advent/events/{day}/likes` | `{"count": 42, "liked": true}` |
| PUT | `/api/advent/events/{day}/like` | тело `{"liked": true}`, ответ `{"count": 43, "liked": true}` |

`day` — номер 1–31 в рамках кампании 2026. В следующих кампаниях лучше добавить идентификатор кампании, чтобы лайки разных лет не смешивались.

Запросы используют `credentials: "include"`, если API находится на том же домене или корректно настроен CORS. Хост приложения отвечает за cookie/сессию и CSRF-защиту; токены не прописывать в HTML.

## Встраивание через адаптер

Если приложение использует собственный auth bridge, можно до запуска календаря присвоить объект:

```js
window.AdventLikesAdapter = {
  async getSummary(day) { /* { count: number, liked: boolean } */ },
  async setLike(day, liked) { /* { count: number, liked: boolean } */ }
};
```

Он имеет приоритет перед `ADVENT_CONFIG.apiBase`. Запросы и проверку доступа реализует приложение.

## Режим GitHub Pages

Если `window.AdventLikesAdapter` и `window.ADVENT_CONFIG.apiBase` отсутствуют, текущий HTML использует старый `localStorage` только для визуального прототипа. Это **не** общий счётчик и не production-решение.

## Что требуется перед интеграцией

1. Уточнить реальные endpoint'ы существующего сервера, схему авторизации, CORS и CSRF.
2. Ввести серверную уникальность `(campaign_id, event_id, user_id)` и атомарные операции `PUT`; запретить повторные/чужие лайки.
3. Определить политику GDPR/персональных данных и срок хранения идентификаторов.
4. Проверить один и тот же лайк с двух устройств/профилей, отключение сети, 401/403/500.
5. Определить временную зону кампании. Таймер в v8 сейчас считает до полуночи **устройства**, а `timeZone` меняет только определение текущего дня; если нужен единый момент Нового года для всех, контракт таймера предстоит согласовать.
